# approval-excel 0.14.4 — 생성·검증·다운로드 전달 경로 보완

## 관찰 및 원인 범위

사용자 화면에서는 원본 재첨부를 요구하며 파일 생성 없이 종료했다. 기준 커밋 `02e85a2b090141b8137628d32c28cd41330a0115`에는 이미 두 원본과 생성기가 있다. 따라서 저장소의 양식 누락은 아니다. 기존 지침은 접근 불가 시 중단하도록 했고, 파일 마운트가 없는 환경의 복구 경로나 실제 실행 증거를 요구하지 않았다. 생성기 내부에도 저장 후 검증 게이트가 없었다. 실제 실패 대화의 도구 로그나 설치 버전은 확보하지 못했으므로 정확한 호스트 측 원인을 단정하지 않는다.

## 암묵지를 실행 계약으로 전환

- 원본은 개발자 PC가 아니라 플러그인 배포 자산이다. 사용자가 다시 첨부할 자료가 아니다.
- 경기도 XLS 5열과 경기도 외 XLSX 9열은 서로 다른 원본이다. 그대로 복원하고 입력 셀만 채운다.
- 파일 작성 설명, 코드, 표는 다운로드 가능한 실제 파일의 대체물이 아니다.
- 원본 파일이 마운트되지 않은 상황과 코드 실행 도구 자체가 없는 상황은 다르다. 전자는 포함된 텍스트 실행본으로 복원하고, 후자는 호스트 제약으로 정확히 안내한다.
- 저장 성공과 검증 성공을 구분한다. 독립적으로 다시 읽어 확인한 파일만 최종 다운로드 경로에 공개한다.

## 재현 명령

```sh
python verification/package_approval.py
python -m unittest discover -s verification -p 'test_approval*.py' -v
git diff --check
```

사용자 화면의 품목 금액 사례(3×7,650원, 1×99,000원)를 두 지역 양식에 넣어 파일을 재열고 검증했다. 규격 없음은 테스트 픽스처에서 명시했으며 실제 사용자 입력을 추정하는 규칙으로 사용하지 않는다. 경기도 외 예상금액은 22,950원·99,000원이고 총합 121,950원은 파일에 합계 행으로 넣지 않는다.

텍스트 복원 경로는 원본 경로와 site-packages를 사용할 수 없는 `python -I -S` 별도 프로세스에서도 XLSX를 생성한다. 경기도 XLS는 기존 xlrd/xlwt/xlutils 의존성을 사용한다. XLS 복사 과정의 FONT 테이블 인덱스 재배치(5→7)는 표시 속성 변경이 아니므로 인덱스를 제외한 모든 글꼴 속성을 비교한다.

## 검증 한계

검사는 실제 Python 실행 및 생성 파일·배포 패키지에 대한 것이다. 사용자 계정의 ChatGPT 설치 갱신, 대화에서의 스킬 선택·파일 첨부 렌더링, 에듀파인 서버 업로드는 수행하지 않았다. Skills 전용 플러그인은 호스트의 코드 실행 기능을 활성화할 수 없으며 그 기능이 없는 환경에서 파일 생성을 보장하지 않는다. 기존 설치본의 자동 갱신도 이 저장소 업데이트로 입증되지 않는다.
