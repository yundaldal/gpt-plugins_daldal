# 대화 흐름 검증 시나리오

상태: 수정 전후 지침을 읽는 수동 검토 완료. 아래는 실제 모델 대화 실행 결과가 아닌, 호스트에서 실행할 입력과 판정 기준입니다. 정적 자동 검사는 `flow-harness.cjs`가 담당합니다.

각 사례는 새 대화 또는 표시된 선행 상태에서 실행하고, 사용자 입력·모델 응답 전문·기대/관찰 단계·통과 여부를 기록합니다. 실제 실행 시 같은 사례를 최소 3회 반복하고, 한 번이라도 필수 선택을 대신 확정하거나 근거를 지어내면 실패로 기록합니다.

| 대상·상태 | 시험 입력/행동 | 기대 결과·금지 사항 | 수정 전후 지침 검토 |
|---|---|---|---|
| 학교 품의 시작 | 시작 | 1단계 품의 유형 선택, 최종 문안 없음 | 유형 질문 유지 |
| 학교 품의 자료 선입력 | 품목·수량·단가가 있는 견적서 제공, 유형 미지정 | 자료 재입력 없이 유형 확인, 이후 분석 확인 | 재사용·단계 조건 명시 |
| 학교 품의 누락 | 배송비가 있는지 모름 | 필수 금액 확인 대기, 0원으로 임의 확정 금지 | 자동 보완 충돌 제거 |
| 학교 품의 생성 | 분석 요약 뒤 '맞아요, 작성해줘' | 확인된 정보로 문안과 엑셀 작성 | 생성 게이트 명시 |
| 학교 품의 수정 | 수량을 3개로 바꿔 | 산식·합계를 갱신하고 다시 확인 | 복귀 조건 추가 |
| IEP 설계 시작 | 이전학기 문서 없어요 | 선택 업로드를 강요하지 않고 기본 정보 요청 | 1·2단계 분리 |
| IEP 설계 누락 | 학생 이니셜과 학년만 제공 | 과목·교육과정·기간·현행 수준 등 부족한 정보 요청 | 조건 명시 |
| IEP 설계 확인 | 현재수준 제시 후 '다음 단계로' | 학기 목표까지만 작성하고 대기 | 전체 자동 승인 방지 |
| IEP 설계 자료 부재 | 성취기준 파일 접근 실패 | 파일 요청, 임의 코드 생성 금지 | 실패 시 대기 명시 |
| IEP 설계 완료 | 모든 단계 확인 후 '작성 완료' | 종료, 새 학생 요청 시 1단계 | 완료·재시작 명시 |
| IEP 평가 시작 | 3개 교육내용이 있는 계획 제공 | 3개를 제시하고 첫 관찰 입력 요청 | 실제 항목 수 명시 |
| IEP 평가 누락 | 목표 80%, 실제로는 잘했어요 | 실제 관찰 질문, 80% 성취로 단정 금지 | 잘못된 보완 예시 제거 |
| IEP 평가 일괄 입력 | 세 항목 관찰 한 번에 제공 | 관찰 보관, 첫 평가문 확인 후 다음 항목 | 입력 재요청 없이 순차 확인 |
| IEP 평가 수정 | 7개가 아니라 6개였어요 | 현재 문장 수정 및 재확인 | 대기 명시 |
| IEP 평가 모름 | 횟수는 기록 안 했어요 | 관찰 행동으로만 표현, 수치 발명 금지 | 사실과 목표 구분 |
| IB 핵심개념 | 수업 맥락을 모두 제공 | 개념 후보와 선택 질문, 일반화 선행 생성 금지 | 분석/선택 단계 구별 |
| IB 핵심개념 선택 | 첫 번째 개념으로 | 일반화 5개 이상과 선택 질문 | 기존 산출 규칙 유지 |
| IB 핵심개념 질문 | 일반화란 무엇인가요 | 설명 후 현재 선택 대기 | 중간 질문 복귀 명시 |
| IB 핵심개념 변경 | 앞의 개념을 바꿀게 | 종속 일반화·탐구질문 재확인 | 변경 조건 추가 |
| IB 전체 설계 | 자료를 모두 주며 바로 완성 요청 | 기본정보를 재사용하고 개념·렌즈 선택 순서 유지 | 포괄 요청과 확인 구별 |
| IB 전체 설계 5단계 | B 선택, 프로젝트 이름 없음 | 이름만 질문하고 대기, 지도안 생성 금지 | 두 조건 모두 요구 |
| IB 전체 설계 자료 부재 | 참조 문서 없음 | 자료 또는 자료 없이 진행 선택 요청 | 문서 읽었다는 주장 금지 |
| IB 전체 설계 수정·완료 | A로 수정 후 재확인, 최종 C | 현재 단계 재확인 후 완료 | 원래 A/B/C 유지 |
| 캔바 시작 | 게임 만들어줘 | 필수 정보 1~3개 질문 | 기존 흐름 유지 |
| 캔바 충분한 입력 | 대상·목표·자료 모두 제공 | 재질문 없이 프롬프트 작성, UDL·회복 UX 포함 | 기존 흐름 유지, 업로드 안내만 추가 |
| 캔바 초안 요청 | 질문 없이 초안으로 | 가정 명시, 정답 사실 발명 금지 | 원래 예외 유지 |
| 공문 이미지 없음 | 관련문서 뽑아줘 | 캡처 요청, 예시를 추출 결과로 쓰지 않음 | 입력 대기 명시 |
| 공문 명확한 캡처 | 번호·일자·제목이 명확한 가상 이미지 | 바로 형식 정리, 불필요한 승인 없음 | 즉시 추출 유지 |
| 공문 흐린 캡처 | 번호 6/8 구별 불가 | 후보·미확인 행 분리, 확인 대기 | 추정과 확정 구분 |
| 공문 정정 | 8이 아니라 6입니다 | 해당 행 수정 후 결과 제공 | 확인 루프 명시 |

공통 회귀 조건: 기존 형식·자료·기능을 유지하고 질문 뒤 답변 없이 다음 결과를 생성하지 않습니다. 캔바의 명시적 초안 예외와 명확한 공문 이미지의 즉시 추출에는 불필요한 승인 단계를 추가하지 않습니다.

업로드 공통 추가 검사(7종 각각): 자료가 없을 때 요청하는 자료를 구체적으로 안내하는가, 사용자가 올린 파일이 해당 대상·기간·주제인지 확인하는가, 읽히지 않는 부분만 다시 요청하는가, 이미 올린 자료를 중복 요청하지 않는가, 선택 업로드를 강제로 요구하지 않는가. 실제 모델 실행 결과는 아직 기록하지 않았습니다.
