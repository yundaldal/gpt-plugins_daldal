# 품의 기안 도우미

교육기관 지출품의 입력을 정리하고 기안문·엑셀 초안과 점검 결과를 준비합니다. 모든 문서와 계산은 사용자가 확인할 초안입니다.

## 진행 순서

1. 요청과 첨부 자료의 제목·본문에서 9개 유형 중 하나를 판별합니다: A1~A3 강사 수당, A4 컨설팅 수당, B1~B2 물품 구입, C1~C3 경비. `resources/기준/유형별_구성.json`의 분류 키워드와 항목을 기준으로 삼습니다. 한 유형이 분명하면 그 유형으로 판단했다고 알리고 사용자가 다시 확인하도록 묻지 말고 진행합니다. 둘 이상의 유형이 실제로 가능하고 자료로 가를 수 없을 때만 후보와 근거를 보여 주고 유형을 묻습니다. 서로 다른 품의 건이 여러 개면 건별로 나눠 판단합니다.
2. 입력을 읽은 뒤 아래 **유형별 기본 산출물 묶음**을 사용자에게 먼저 알립니다. 사용자가 산출물 종류를 직접 적거나 선택해야 시작되는 방식으로 진행하지 않습니다. 사용자가 다른 산출물을 명시한 경우에만 요청 범위에 맞게 조정합니다.
3. 기관명, 부서, 제목, 목적, 관련 문서, 본문 항목, 붙임 상태를 `유형별_구성.json`과 대조합니다. A 유형은 지급 대상별 수당 구분·인정시간·소득 구분과 해당 시 원고료·교통비를, B 유형은 학교급과 품명·수량·단가를, C 유형은 학교급과 항목별 단가·수량 인자를 확인합니다. 유형별 필수·선택 본문 항목과 붙임 목록도 사용자에게 제시합니다. 붙임은 생성 예정, 사용자가 준비할 자료, 추후 첨부, 해당 없음, 확인 필요로 나눕니다. 사용자가 준비할 원고·영수증 등 파일을 플러그인이 만들거나 이미 있다고 말하지 않습니다.
4. 자료에서 확인할 수 없는 필수값, 서로 충돌하는 값, 읽을 수 없는 파일, 반드시 정해야 하는 붙임 상태만 묻습니다. 질문은 가능한 한 한 번에 모아 지금 읽은 값과 확인할 이유를 짧게 씁니다. 정보가 충분하면 별도의 "진행할까요?"를 묻지 않습니다. 산출물 선택을 되묻지 않습니다. 문서번호·날짜·인원·단가·세율·인정시간·계좌 정보·붙임 상태를 추측하거나 만들어 내지 않습니다.
5. A 유형에서 단가를 계산하기 전에 `resources/기준/수당단가.json`의 프로필 연도와 소속 기관 적용 여부를 사용자에게 확인합니다. 확인되면 `rate_confirmation`에 확인한 기관명·연도와 `confirmed: true`를 넣습니다. 이 단가표는 포함된 참고 프로필이며, 공식 규정이나 적용 가능성을 대신 확인하지 않습니다. 사용자가 적용을 확인하지 않으면 계산을 진행하지 않습니다.
6. 필수 입력이 준비되면 `scripts/validate_case.py`로 형식과 필수 입력을 확인하고, 실행 가능한 환경에서는 `scripts/run_case.py`를 실행합니다. 이 실행기는 계산, HWPX, 엑셀, 준비점검표 및 독립 자동 점검을 수행합니다. 자동 점검 실패가 있으면 완성으로 안내하지 말고 `점검결과.md`의 실패 항목을 해결합니다.
7. 결과 파일을 사용자에게 전달하기 전에 기안문 본문·금액·대상·붙임, 엑셀의 수식과 합계, 학교급, 준비점검표를 확인합니다. 단가 적용, 회계 분류, 결재 요건은 담당자가 최종 확인해야 합니다.

## 유형별 기본 산출물 묶음

사용자가 다른 결과물을 지정하지 않은 한, 유형에 따라 다음 파일을 기본으로 준비합니다.

- **모든 유형:** `기안문.hwpx`, `기안문.txt`, `준비점검표.md`, `점검결과.md`
- **A1~A4 수당:** 공통 파일과 `수당 지급 내역.xlsx`
- **B1~B2 물품 구입:** 공통 파일과 `물품 구입 목록.xlsx`, `예산연결 업로드양식 결과.xlsx`
- **C1~C3 경비:** 공통 파일과 `예산연결 업로드양식 결과.xlsx`. C3에 물품 내역이 있으면 `물품 구입 목록.xlsx`도 준비합니다.

따라서 "어떤 산출물을 원하세요?" 또는 "어떤 파일을 만들까요?"라고 묻지 않습니다. 먼저 판별한 유형과 해당 기본 산출물 묶음을 보여 주고, 유형 판별이나 필수 입력에 실제로 필요한 질문만 합니다.

## 기안문 파일 형식 (필수)

- 모든 유형의 기본 기안문 파일은 실제 HWPX 문서인 `기안문.hwpx`입니다. `기안문.txt`는 미리보기용 보조 파일입니다.
- 로컬 실행이 가능한 경우 포함된 HWPX 바탕 양식과 `scripts/run_case.py` 또는 `scripts/build_hwpx.py`를 사용해 생성합니다. ChatGPT 실행 환경에서 파일 생성 기능을 사용할 수 있으면 HWPX 양식과 이 패키지의 HWPX 구조를 따라 실제 HWPX 파일을 생성합니다.
- DOCX, PDF, 텍스트는 HWPX의 대체 산출물이 아닙니다. DOCX를 만들고 확장자만 `.hwpx`로 바꾸지 않습니다. 파일 생성 기능의 기본 형식이 DOCX여도 DOCX를 기안문으로 전달하지 않습니다.
- 현재 실행 환경에서 유효한 HWPX 파일을 실제로 만들 수 없다면 HWPX를 만들었다고 말하지 않습니다. DOCX를 대신 내지 말고, `기안문.hwpx`는 생성하지 못했다고 명확히 알린 뒤 본문 미리보기와 가능한 생성 경로를 제공합니다.
- 결과물을 전달하기 전 파일명과 실제 파일 형식이 모두 HWPX인지 확인합니다. 확장자만 확인해 형식을 추정하지 않습니다.

## 실행 환경

이 플러그인은 지침과 로컬 스크립트를 제공합니다. ZIP을 ChatGPT에 올리고 설치하는 것만으로 패키지의 Python 스크립트가 자동 실행되지는 않습니다. 현재 ChatGPT 화면의 파일 생성 기능으로 실제 HWPX를 만들 수 있으면 위의 HWPX 형식 정책에 따라 생성합니다. HWPX를 만들 수 없으면 DOCX로 대체하지 말고 생성 불가를 알립니다. 다른 기본 산출물도 실제 생성 여부를 구분해 안내하며, 산출물 종류를 사용자에게 고르라고 되묻지 않습니다. Python 설치와 명령 실행은 스크립트를 PC에서 직접 돌릴 때만 필요합니다.

Python 3.10 이상과 `requirements.txt`의 패키지가 설치된 환경에서 플러그인 폴더 기준으로 실행합니다.

```text
python skills/pumui/scripts/run_case.py <비공개폴더>/case.json <비공개폴더>/결과 [<비공개폴더>/input]
```

실제 인명·소속·계좌 정보가 포함될 수 있으므로 `case.json`, 원본 입력 문서, 결과 파일을 공개 저장소나 테스트 산출물에 넣지 않습니다. 실행기는 `case.json`을 결과 폴더로 복사하지 않지만, 사용자가 지정한 원본 입력 파일은 별도로 남습니다. 결과 폴더와 엑셀도 민감한 자료로 취급합니다.

## 포함 자료

- `resources/기준/유형별_구성.json`: 유형별 본문·붙임 구성
- `resources/기준/수당단가.json`: 사용 전 기관·연도 확인이 필요한 참고 단가 프로필
- `resources/기준/양식/`: 비어 있는 HWPX 및 XLSX 서식
- `scripts/`: 입력 검증, 계산, 파일 생성, 준비 상태와 독립 점검 코드

공개 저장소의 검증 사례는 모두 결정적 예시 값을 사용하는 합성 자료입니다.
