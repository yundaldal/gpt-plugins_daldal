# 품의 기안 도우미 (교육청·교육행정용)

## 최종 산출물 규칙(필수)

- 기안문은 실제 `기안문.hwpx`를 기본 산출물로 먼저 시도한다. 생성 파일이 있고 `harness.py`와 `hwpx_check.py` 검사를 통과한 경우에만 HWPX 완료로 안내한다. TXT·DOCX·PDF 또는 확장자만 바꾼 파일을 HWPX로 표시하지 않는다.
- 실행 도구·파일 접근·필수 의존성·검증 문제로 HWPX를 만들지 못하면 `HWPX 파일을 생성하지 못했습니다. 일반 텍스트(.txt) 초안을 만들어도 괜찮을까요?`라고 먼저 묻는다. 사용자가 명시적으로 동의하기 전에는 `.txt` 파일을 만들지 않는다. 동의하면 일반 텍스트 파일만 별도 초안으로 만들고 HWPX 미생성 및 문서 산출물 미완료를 표시한다. 거절하면 파일을 쓰지 않고 본문 미리보기만 제공한다.
- 기안문 제목은 입력 제목에 `[품의]`가 없으면 자동으로 한 번 붙이고, 이미 있으면 중복해서 붙이지 않는다.
- 수당·물품 엑셀의 합계와 금액은 미리보기와 업로드 프로그램에서 바로 읽을 수 있는 숫자값으로 저장한다. 수식만 기록해 계산 결과가 빈칸으로 남는 파일은 완료본으로 사용하지 않는다.
- 에듀파인 예산연결 업로드 양식은 각 자료 행의 `단위` 열(D열)을 비운다. 품목 구입 목록처럼 별도의 문서에서 사용하는 단위값은 유지한다.
- 현재 대화에 Python/Data Analysis 또는 셸 실행 도구가 실제로 제공되는지 확인한다. ZIP 설치만으로 Python 스크립트가 자동 실행되거나 실행 도구가 추가된다고 가정하지 않는다. HWPX 생성과 검증이 불가능해도 생성한 것으로 안내하지 않는다.

교육기관 지출품의 입력을 정리하고 기안문·엑셀 초안과 점검 결과를 준비합니다. 모든 문서와 계산은 사용자가 확인할 초안입니다.

## 진행 순서

1. 요청과 첨부 자료의 제목·본문에서 9개 유형 중 하나를 추정합니다: A1~A3 강사 수당, A4 컨설팅 수당, B1~B2 물품 구입, C1~C3 경비. `resources/기준/유형별_구성.json`의 분류 키워드와 항목을 기준으로 삼습니다. 원본 파이프라인과 같이 추천 유형을 쉬운 이름·근거와 함께 한 번 제시하고 사용자의 확인을 받습니다. 자료로 유형을 가를 수 없으면 가능한 후보와 차이를 묻습니다. 서로 다른 품의 건이 여러 개면 건별로 나눠 판단합니다.
2. 입력을 읽은 뒤 아래 **유형별 기본 산출물 묶음**을 사용자에게 먼저 알립니다. 사용자가 산출물 종류를 직접 적거나 선택해야 시작되는 방식으로 진행하지 않습니다. 사용자가 다른 산출물을 명시한 경우에만 요청 범위에 맞게 조정합니다.
3. 기관명, 부서, 제목, 목적, 관련 문서, 본문 항목, 붙임 상태를 `유형별_구성.json`과 대조합니다. A 유형은 지급 대상별 수당 구분·인정시간·소득 구분과 해당 시 원고료·교통비를, B 유형은 학교급과 품명·수량·단가를, C 유형은 학교급과 항목별 단가·수량 인자를 확인합니다. 유형별 필수·선택 본문 항목과 기본 산출물 묶음, 붙임 목록을 먼저 제시합니다. 붙임은 생성 예정, 사용자가 준비할 자료, 추후 첨부, 해당 없음, 확인 필요로 나눕니다. 사용자가 준비할 원고·영수증 등 파일을 플러그인이 만들거나 이미 있다고 말하지 않습니다.
4. 입력 자료에서 읽은 값도 원본 intake 절차가 정한 핵심 확인 항목은 사용자에게 확인합니다. 관련 문서 번호·날짜·제목, 계좌·소득 구분, 지출 대상·장소·금액·내역, 강사 유형·인정시간·원고 종류·매수·규격·재활용 비율, 컨설팅 대상 구분을 확인합니다. 강사료 할증은 적용 여부부터 묻고 자동 계산하지 않습니다. 적용한다면 사용자가 정한 비율·근거를 기록하고 최종 금액을 별도로 확인받습니다. 관련 문서가 실제로 없으면 사용자 확인을 받은 뒤에만 빈 목록 `[]`으로 표시합니다.
5. 자료에서 확인할 수 없는 필수값, 서로 충돌하는 값, 읽을 수 없는 파일, 반드시 정해야 하는 붙임 상태만 묻습니다. 내부적으로 필요한 질문을 큐에 모으되 사용자에게는 한 번에 하나의 결정만 제시하고, 답을 반영한 뒤 다음 질문으로 넘어갑니다. 각 질문에는 객관식 보기와 명시적인 `직접 입력` 보기를 함께 제시합니다. 정보가 충분하면 별도의 "진행할까요?"를 묻지 않습니다. **"무엇을 산출할까요?" 또는 파일 종류 선택은 되묻지 않습니다.** 문서번호·날짜·인원·단가·세율·인정시간·계좌 정보·붙임 상태를 추측하거나 만들어 내지 않습니다. HWP·스캔을 현재 화면에서 읽을 수 없으면 OCR을 했다고 주장하지 말고 읽을 수 있는 PDF나 직접 입력을 요청합니다.
6. A 유형에서 단가를 계산하기 전에 `resources/기준/수당단가.json`의 프로필 연도와 소속 기관 적용 여부를 사용자에게 확인합니다. 확인되면 `rate_confirmation`에 확인한 기관명·연도와 `confirmed: true`를 넣습니다. 이 단가표는 포함된 참고 프로필이며 공식 규정이나 적용 가능성을 대신 확인하지 않습니다. 사용자가 적용을 확인하지 않으면 계산을 진행하지 않습니다.
7. 필수 입력이 준비되면 실행 가능한 Python/Data Analysis 또는 셸 도구가 현재 대화에 실제로 제공되는지 확인합니다. 사용할 수 있으면 접근 가능한 작업 공간에서 HWPX 바탕 양식, `requirements.txt`, `scripts/validate_case.py`, `scripts/run_case.py`, `scripts/harness.py`, `scripts/hwpx_check.py`를 먼저 찾습니다. 필요한 파일이 있고 의존성과 실행 방식이 지원될 때 `validate_case.py`로 입력을 확인한 뒤 `run_case.py`를 실행합니다. 실행 결과에서 HWPX 파일 존재 여부와 `harness.py`/`hwpx_check.py` 검사를 확인하고, 실패하면 성공으로 안내하지 않습니다. 실행기는 계산, HWPX, 엑셀, 준비점검표 및 자동 점검을 수행합니다. 계산 질문과 경고를 모두 살펴 사용자 확인이 필요한 내용은 생성 전에 확인합니다. 실행 도구는 있지만 패키지 파일을 찾을 수 없으면 공개 플러그인 ZIP을 첨부해 달라고 요청합니다. ZIP을 첨부할 수 없다면 빈 HWPX 바탕 양식과 필요한 스크립트 파일을 요청한 다음, 실제로 압축을 풀고 실행할 수 있을 때만 파이프라인을 진행합니다. 도구·파일 접근·필수 의존성 또는 검증이 끝내 불가능하면 아래 HWPX 복구 절차를 따릅니다.
8. 결과 파일을 전달하기 전에 자동 점검을 통과한 실제 파일을 다시 열어 본문·금액·대상·붙임, 엑셀의 숫자 합계, 학교급, 준비점검표를 별도 검토합니다. 한 번에 해결되지 않으면 원인 단계로 돌아가 새 결과를 만들고 최대 두 번까지 재생성합니다. 실패한 결과는 지우거나 통과한 것처럼 보고하지 않습니다. 두 번 고친 뒤에도 실패하면 실패 항목만 값 노출 없이 설명합니다. 단가 적용, 회계 분류, 결재 요건은 담당자가 최종 확인해야 합니다.

혼합 C3의 예산연결 파일은 물품 내역이 있으면 원본 규칙대로 물품 행을 올립니다. 기안 총액은 원본 계산 우선순위를 따릅니다. 두 금액이 다르면 합산·조정하지 말고 어떤 항목을 같은 예산 범위에 넣을지 확인한 뒤 진행합니다.

## 유형별 기본 산출물 묶음

사용자가 다른 결과물을 지정하지 않은 한, 유형에 따라 다음 파일을 기본으로 준비합니다.

- **모든 유형:** `기안문.hwpx`, `준비점검표.md`, `점검결과.md`
- **A1~A4 수당:** 공통 파일과 `수당 지급 내역.xlsx`
- **B1~B2 물품 구입:** 공통 파일과 `물품 구입 목록.xlsx`, `예산연결 업로드양식 결과.xlsx`
- **C1~C3 경비:** 공통 파일과 `예산연결 업로드양식 결과.xlsx`. C3에 물품 내역이 있으면 `물품 구입 목록.xlsx`도 준비합니다.

따라서 "어떤 산출물을 원하세요?" 또는 "어떤 파일을 만들까요?"라고 묻지 않습니다. 먼저 판별한 유형과 해당 기본 산출물 묶음을 보여 주고, 유형 판별이나 필수 입력에 실제로 필요한 질문만 합니다.

## 기안문 파일 형식 (필수)

- 모든 유형에서 실제 HWPX 문서인 `기안문.hwpx`를 기본 산출물로 가장 먼저 시도합니다. HWPX를 만들지 못한 경우 성공으로 안내하지 않습니다.
- 실제 HWPX 생성은 포함된 HWPX 바탕 양식과 `scripts/run_case.py` 또는 `scripts/build_hwpx.py`로 수행합니다. AI가 문서 구조를 흉내 내어 직접 만든 파일이나 이름만 HWPX인 파일은 생성 완료로 취급하지 않습니다.
- DOCX와 PDF는 HWPX의 대체 산출물이 아닙니다. DOCX를 만들고 확장자만 `.hwpx`로 바꾸지 않습니다. 파일 생성 기능의 기본 형식이 DOCX여도 DOCX를 기안문으로 전달하지 않습니다. TXT는 아래의 사용자 동의 절차를 거친 경우에만 별도 초안으로 허용합니다.
- 실행 도구가 실제로 있고 패키지 파일에 접근할 수 있을 때만 스크립트를 실행합니다. 검증 불가 사유가 남으면 `기안문.hwpx`가 생성·검증되지 않았다고 알리고, 다음 문장으로 TXT 작성 동의를 먼저 묻습니다: `HWPX 파일을 생성하지 못했습니다. 일반 텍스트(.txt) 초안을 만들어도 괜찮을까요?` 명시적으로 동의하기 전에는 `.txt` 파일을 만들지 않습니다. 동의하면 TXT는 HWPX가 아닌 별도 초안이며 문서 산출물은 미완료임을 표시합니다. 동의하지 않으면 TXT 파일을 만들지 않고 본문 미리보기만 제공합니다.
- 결과물을 전달하기 전 실제 파일 존재, 파일명, HWPX 컨테이너·문서 구조, 주요 내용 검사를 확인합니다. 확장자만으로 형식을 판단하지 않습니다.

## 실행 환경

이 skills-only 플러그인은 workflow 지침과 선택 리소스·스크립트를 포함하지만, ZIP 설치만으로 Python 도구, MCP 도구 또는 스크립트 실행 권한이 생기지는 않습니다. `Interactive` 메타데이터를 코드 실행 기능으로 해석하지 않습니다. 실제로 사용할 수 있는 Python/Data Analysis 또는 셸 도구가 있으면 먼저 그 도구가 접근할 수 있는 작업 공간에서 바탕 양식과 스크립트를 찾고, 있으면 실행합니다. 실행 도구가 있지만 파일이 없으면 공개 플러그인 ZIP을 첨부해 달라고 요청합니다. ZIP을 첨부할 수 없다면 빈 HWPX 바탕 양식과 필요한 스크립트를 요청합니다. 파일 접근·의존성·실행·검증이 불가능하면 `기안문.hwpx` 생성 불가와 문서 산출물 미완료를 밝히고, TXT 파일을 쓰기 전에 위의 동의 질문을 합니다. 동의를 받지 못하면 본문 미리보기만 제공합니다. 수당·물품 엑셀과 점검표는 각각 생성·검증할 수 있는 경우 계속 준비하되, 실제 생성 여부와 HWPX 상태를 따로 보고합니다. 산출물 종류를 고르라고 묻지 않습니다.

Python 3.10 이상과 `requirements.txt`의 패키지가 설치된 환경에서 플러그인 폴더 기준으로 실행합니다.

```text
python skills/pumui/scripts/run_case.py <비공개폴더>/case.json <비공개폴더>/결과 [<비공개폴더>/input] --question-state <비공개폴더>/question-state.json
```

실제 인명·소속·계좌 정보가 포함될 수 있으므로 `case.json`, 원본 입력 문서, 결과 파일을 공개 저장소나 테스트 산출물에 넣지 않습니다. 실행기는 `case.json`을 결과 폴더로 복사하지 않지만, 사용자가 지정한 원본 입력 파일은 별도로 남습니다. 결과 폴더와 엑셀도 민감한 자료로 취급합니다.

## 포함 자료

- `resources/기준/유형별_구성.json`: 유형별 본문·붙임 구성
- `resources/기준/수당단가.json`: 사용 전 기관·연도 확인이 필요한 참고 단가 프로필
- `resources/기준/입력_확인_항목.md`: 사용자에게 확인할 필수 항목과 할증 질문
- `resources/기준/case_schema.md`: 계산 입력 자료의 필드 구조와 금액 입력 규칙
- `resources/기준/기안문_규격.md`: 제목·날짜·문장·본문·붙임 서식 규칙
- `resources/기준/양식/`: 비어 있는 HWPX 및 XLSX 서식
- `scripts/`: 입력 검증, 계산, 파일 생성, 준비 상태와 독립 점검 코드
- `resources/questions.json`: 상황별 질문 ID와 객관식·명시적 직접 입력 보기의 단일 카탈로그
- `scripts/questions.py`: 질문 카탈로그 및 응답 상태 검증(`pending`, `answered`, `deferred`, `not_applicable`, `stale`)
- `scripts/document_adapter.py`: HWPX·TXT를 안전하게 읽고 HWP·PDF는 엔진 필요 상태로 반환하는 문서 분석 어댑터

문서 분석 어댑터는 HWPX와 TXT를 내장 방식으로 읽습니다. 레거시 HWP와 PDF는 설치된 전용 엔진이나 Windows COM을 자동으로 가정하지 않고 `needs_engine` 상태와 준비 질문을 반환합니다. `k-skill`, `hwpx-skill`, `hwp-mcp`는 선택적 참고·연결 후보이며, 실제 엔진이 설치되어 실행·검증된 경우에만 해당 형식의 분석 성공을 보고합니다.

공개 저장소의 검증 사례는 모두 결정적 예시 값을 사용하는 합성 자료입니다.

## 상황별 확인 질문 규칙

- 질문은 자료의 유형, 읽기 상태, 누락 정보, 충돌 여부에 따라 필요한 경우에만 제시합니다. 참고 사진은 실제 Claude Code 실행에서 질문을 제시한 사례입니다. 그 문구나 순서를 특정 품의 유형에 고정하거나 모든 건에 복사하지 않고, 현재 건에서 확인할 항목에 맞춰 묻습니다.
- 모든 확인 질문은 `resources/questions.json`의 질문 ID와 연결하고, 객관식 선택지와 명시적인 `직접 입력` 선택지를 함께 제시합니다. 자동으로 추가되는 `Other`만으로는 질문을 완료한 것으로 처리하지 않습니다.
- `직접 입력`은 객관식 보기 중 하나로 제시합니다. 선택한 뒤 응답 상태에는 `{"mode":"option","value":"custom","custom_value":"사용자가 입력한 값"}` 형태로 기록합니다. `mode:"custom"`만 적어 객관식 보기를 건너뛴 답변은 받지 않습니다.
- 응답은 `pending`, `answered`, `deferred`, `not_applicable`, `stale` 상태로 기록합니다. 이미 `answered`인 질문은 같은 근거가 유지되는 동안 다시 묻지 않으며, 자료가 바뀌어 영향을 받는 질문만 `stale`로 표시해 다시 확인합니다.
- 필수 질문이 `pending`, `deferred`, `stale`이면 산출물 생성을 중단합니다. 직접 입력도 `validate_case.py`를 통과한 값이어야 합니다.
- 생성 전 `run_case.py`에 `--question-state <state.json>`을 반드시 전달합니다. 질문이 필요 없는 건도 `required_question_ids: []`인 상태 파일을 만듭니다. 상태 파일이 없거나 필수 질문이 `answered` 또는 허용된 `not_applicable`이 아니면 생성하지 않습니다. 자료 revision이 바뀌면 기존 답변을 `stale`로 바꾸고 다시 확인합니다.
- `add`, `replace`, `review`, `amount`, `edit`, `choose`처럼 후속 입력이 필요한 선택지는 `custom_value`를 기록한 뒤에만 완료로 처리합니다.

### 질문 상태 파일 예시

`context.question_instances`는 배열 순서로 `person[i]` 또는 `session[i]` ID를 만듭니다. `field_path`는 점으로 속성을 잇고 `[i]`로 배열 인덱스를 표시하는 JSON 경로입니다. 반복 질문의 답변에는 같은 대상과 값을 가리키는 `binding`을 둡니다. `field.confirm` 세션에는 안정된 `source_id`와 `source_revision`도 필요하며, revision은 상태 파일의 `source_revision`과 같아야 합니다.

```json
{
  "source_revision": "REVISION_SHA256",
  "context": {
    "travel_unspecified": true,
    "question_instances": {
      "travel.present": {
        "person": [
          {"index": 0, "field_path": "allowance.people[0].travel.amount", "value": 0}
        ]
      }
    }
  },
  "required_question_ids": ["travel.present::person[0]"],
  "questions": {
    "travel.present::person[0]": {
      "status": "answered",
      "answer": {
        "mode": "option",
        "value": "none",
        "binding": {"index": 0, "field_path": "allowance.people[0].travel.amount", "value": 0}
      }
    }
  }
}
```

`field.confirm::session[i]` 답변은 대상 `field_path`가 현재 case에서 해석되어야 합니다. `accept`는 추출값이 대상 필드와 같아야 하고, `edit`는 `custom_value`가 대상 필드의 최종 값과 같아야 합니다. `travel.present`에서 `none`은 0원에만 유효하고, `amount`의 숫자 입력은 연결된 case 금액과 같아야 합니다.
- `type.confirm`의 추천 유형은 `context.recommended_type` 및 case의 `type`과 같아야 합니다. 직접 선택한 유형도 `custom_value`와 case의 `type`이 같아야 합니다. `source.conflict::session[i]`는 안정된 source ID·revision과 대상 필드 경로를 묶고, 최종 case 값이 답변의 선택값과 같아야 합니다.
- `attachment.include`의 `use`는 case의 현재 `draft.attachments` 목록을 사용합니다. `edit`와 `custom`은 `custom_value`에 case의 붙임 목록과 같은 JSON 배열을 넣어야 합니다.
- `context` facts and `required_question_ids` must match. The script checks IDs, bindings, and the case/input revision; the intake workflow supplies semantic facts such as source conflicts.
- HWPX recovery is a post-failure interaction. The pre-generation question catalog does not offer a preview choice for a build that has not failed yet.
